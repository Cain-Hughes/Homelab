# September 2026 — Monitoring, media repairs, and viewing statistics

This month's work focused on understanding failures before automating more actions. I added independent monitoring, repaired download and artwork workflows, and started collecting viewing history to support future storage decisions.

## Monitoring beyond one host

I deployed primary Uptime Kuma on the Pi that also hosts secondary AdGuard Home. A second Kuma on the Docker host checks the Pi and the primary monitoring service, with Telegram notifications. The instances are independent rather than automatically replicated.

I also settled on a layered monitoring model: check the host, the application by LAN address and port, and the domain path separately. DNS services benefit from actual query checks. These checks answer different questions, and local domain checks do not prove the public Internet path works.

## Media profiles and requests

Sonarr now uses a single HD - 720p/1080p profile, with TRaSH-based custom-format preferences and a modest season-pack preference. Existing series were moved onto the remaining profile before unused profiles were removed. Seerr's regular users use the default HD request routes without advanced or 4K selection privileges.

One useful lesson: changing a show's monitoring setting does not cancel downloads already queued. I canceled unwanted pending upgrades separately. An old file already replaced by a completed upgrade cannot be recovered merely by canceling its torrent.

## Download cleanup and archives

The queue investigation found a conflict between archive filename exclusions and multipart archive handling. I allowed supported archive formats while retaining executable/script exclusions, disabled Decluttarr's bad-file selection job, and expanded failed-import matching for executable errors.

Unpackerr now has writable access only to the downloads tree. Public and private tracker cleanup retain different behavior so seeding goals are not treated identically. A dry run preceded live cleanup; the first pass reduced the observed Sonarr queue from 71 entries to 28. Configuration snapshots were kept privately before changes.

Completed downloading, successful extraction, and library import are separate milestones. I now check all three rather than treating a disappearing queue entry as sufficient evidence.

## Artwork and playback

I enabled Sonarr/Radarr NFO and artwork export so Jellyfin can use local identification data and images. A targeted refresh repaired an unmatched-title artwork case without re-downloading its media. Online providers were already configured; the investigation corrected an initial interpretation of an obsolete setting.

A playback investigation also showed that client audio support and bitrate limits can trigger transcoding. The subsequent GPU check found that the Quadro P2000 is visible inside Jellyfin, but the acceleration method is set to None and recent video encoding uses libx264. Enabling and testing NVENC is explicitly deferred until a quiet maintenance window.

## Streamystats

Streamystats 2.20.0 now runs under `/docker/streamystats` using the official all-in-one container, a persistent database, generated private secrets, and a dedicated Jellyfin API key. Initial library/user synchronization completed and live playback was detected.

NPM provides its HTTPS route using the existing wildcard certificate, with Force SSL, HTTP/2, and WebSocket support. I also created an initial local database/configuration backup and an on-demand backup script. Moving backups off-host and scheduling them remain separate work.

The statistics database starts collecting observations now. An empty history does not establish that an old title was never watched, so immediate history-based deletion would be premature.

## Storage and next steps

Hardlinks can make deleting a library copy recover less space than its displayed size. Torrent payloads and snapshots may still retain the same blocks. I am documenting those dependencies before considering automated retention.

Maintainerr and Continue Watching deduplication were evaluated but not installed. The intended cleanup approach includes all-user activity, protection for selected titles, a review period, and coordination with the *arrs. GPU acceleration, deduplication, and Maintainerr will wait until nobody is using the service.

The backup strategy and NAS disk-health investigation remain outstanding. RAIDZ2, VM snapshots, and local configuration copies must not be mistaken for an independent media backup.

This documentation update also fixes stale service inventories, the missing port-sync script link, and an incorrect description of Docker socket access. Public examples omit secrets, personal domains, viewing history, and public IPs; the example media subnet is private and is not a live network migration.
